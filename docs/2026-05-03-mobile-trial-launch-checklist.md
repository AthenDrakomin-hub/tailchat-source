# Mobile 试运营上线清单

## 目标

这份清单用于判断 Mobile 端是否可以作为 Web 试运营的补充验证端进入使用阶段。

当前定位：

- Mobile 暂不是主试运营入口
- Mobile 重点验证窄屏浏览、返回、刷新、恢复与状态表达

---

## Go / No-Go 标准

### 可以进入试运营补充验证阶段

- 能稳定选择工作区并进入
- 顶部状态、刷新、返回、切换动作正常
- 错误、重试、恢复、稳定状态表达清楚
- 入口页具备试运营起步和帮助信息

### 不建议进入试运营补充验证阶段

- 进入后频繁白屏
- 刷新与重试表现不一致
- 恢复成功与首次加载难以区分
- 用户无法判断问题出现后该怎么做

---

## P0 必过项

### 1. 入口链路

- [ ] 移动端入口页可正常打开
- [ ] 默认工作区可正常进入
- [ ] 自定义工作区可正常添加
- [ ] 自定义工作区可正常删除

### 2. 主窗链路

- [ ] 进入当前工作区后可正常浏览
- [ ] 返回动作可用
- [ ] 切换工作区可用
- [ ] 刷新动作可用

### 3. 状态反馈

- [ ] 加载中状态可见
- [ ] 弱网提示可见
- [ ] HTTP 异常提示可见
- [ ] 重试动作可用
- [ ] 恢复成功提示可见
- [ ] 稳定状态提示可持续可见
- [ ] 活动态与稳定态视觉层级有区分

### 4. 支持入口

- [ ] 入口页试运营起步建议可见
- [ ] 文档入口可打开
- [ ] 安全与合规入口可打开
- [ ] 下载说明入口可打开

### 5. 工程基线

- [ ] `client/mobile` 的 `yarn tsc --noEmit -p tsconfig.json` 通过
- [ ] 整仓 `pnpm build` 通过

---

## P1 建议满足项

- [ ] 验证弱网环境下刷新体验
- [ ] 验证错误后切换工作区再进入是否稳定
- [ ] 验证不同屏幕尺寸下入口页支持区仍可读
- [ ] 验证试运营用户是否能理解“先 Web 再 Mobile”的推荐路径

---

## 上线当天建议动作

- [ ] 用默认工作区完成一次进入
- [ ] 主动触发一次刷新
- [ ] 观察恢复成功提示和稳定状态提示
- [ ] 触发一次切换工作区
- [ ] 检查文档、信任、下载说明入口

---

## 首周观察项

- [ ] 是否有人在入口页就不知道下一步做什么
- [ ] 是否有人把 Mobile 当成主入口使用而产生预期偏差
- [ ] 是否有人看不懂“恢复成功”和“连接稳定”的区别
- [ ] 是否有人在错误态下不知道先刷新还是切换工作区

---

## 当前建议结论

如果以上 `P0` 全部通过，则 Mobile 可以作为：

- Web 试运营的补充验证端
- 窄屏体验验证端
- 恢复反馈和状态表达验证端
