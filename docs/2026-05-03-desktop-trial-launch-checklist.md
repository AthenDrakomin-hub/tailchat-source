# Desktop 试运营上线清单

## 目标

这份清单用于判断 Desktop 端是否可以作为 Web 试运营的辅助端进入使用阶段。

当前定位：

- Desktop 不是主试运营入口
- Desktop 是长期使用、常驻使用和恢复链路验证端

---

## Go / No-Go 标准

### 可以进入试运营辅助阶段

- 工作区选择正常
- 主窗加载正常
- 当前工作区状态可见
- 重连、返回选择器、复制地址等动作可用
- 有明确的支持与帮助入口

### 不建议进入试运营辅助阶段

- 无法稳定进入主窗
- 加载失败后无法恢复
- 当前工作区状态与动作不可用
- 用户无法判断出现问题时先做什么

---

## P0 必过项

### 1. 启动器链路

- [ ] Desktop 启动器可正常打开
- [ ] 默认工作区可正常点击进入
- [ ] 自定义工作区可正常添加
- [ ] 自定义工作区可正常删除

### 2. 主窗链路

- [ ] 主窗可正常打开
- [ ] 主窗标题可展示连接 / 同步 / 就绪 / 失败状态
- [ ] 当前工作区菜单可正常打开
- [ ] 当前工作区 host 可见
- [ ] 当前工作区连接状态可见

### 3. 恢复动作

- [ ] 可重新连接当前工作区
- [ ] 可返回工作区选择
- [ ] 加载失败时可重试
- [ ] 加载失败时可返回选择器

### 4. 支持入口

- [ ] 启动器支持区可见
- [ ] 文档入口可用
- [ ] 安全与合规入口可用
- [ ] 下载说明入口可用

### 5. 工程基线

- [ ] `client/desktop build` 通过
- [ ] 整仓 `pnpm build` 通过

---

## P1 建议满足项

- [ ] 至少在 2 个工作区环境上验证
- [ ] 验证长时间驻留后主窗状态仍正常
- [ ] 验证工作区切换回选择器后可重新进入
- [ ] 验证工作区异常时值守人员能给出指导

---

## 上线当天建议动作

- [ ] 用默认工作区完成一次进入
- [ ] 用自定义工作区完成一次进入
- [ ] 在主窗触发一次“重新连接当前工作区”
- [ ] 触发一次“返回工作区选择”
- [ ] 确认支持入口都能打开

---

## 首周观察项

- [ ] 是否有人在启动器阶段就卡住
- [ ] 是否有人进入主窗后不清楚当前工作区状态
- [ ] 是否有人遇到失败但不知道先重连还是先切回 Web
- [ ] 是否有人因为桌面端入口不清楚而回退到 Web

---

## 当前建议结论

如果以上 `P0` 全部通过，则 Desktop 可以作为：

- Web 试运营的辅助端
- 长时间常驻体验验证端
- 恢复链路验证端
