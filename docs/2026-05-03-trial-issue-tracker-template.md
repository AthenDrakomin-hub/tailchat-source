# 试运营问题台账模板

## 使用说明

这份模板用于试运营期间统一记录问题。

适用范围：

- Web 主试运营问题
- Desktop 辅助端问题
- Mobile 补充验证端问题

建议规则：

- 一条问题一条记录
- 每天至少更新一次状态
- `P0 / P1 / P2` 必须统一口径
- 每条问题都要明确责任人与下一步动作

---

## 字段说明

### 基础字段

- `编号`：问题唯一编号，建议从 `TRIAL-001` 开始
- `日期`：首次发现日期
- `来源端`：`Web / Desktop / Mobile`
- `模块`：如登录、动态、群组、私信、联系人、状态页、入口页
- `标题`：一句话描述问题

### 严重级别

- `P0`：阻断主链路，必要时暂停试运营或停止放量
- `P1`：不阻断主链路，但明显影响体验，需要优先处理
- `P2`：优化项或边缘问题，可进入后续迭代

### 状态

- `待确认`
- `处理中`
- `待验证`
- `已解决`
- `已关闭`
- `延期`

## 台账使用建议

### 什么时候必须建问题

以下情况建议必须入台账：

- 登录失败
- 无法进入主界面
- 无法进入群组
- 无法发送私信
- 恢复链路异常
- 页面或客户端频繁白屏
- 状态中心提示异常

### 什么时候可以不单独建问题

以下情况可以先合并到已有问题：

- 同一个根因导致的重复反馈
- 明确属于已有问题的重复案例
- 纯文案微调且已纳入同一优化项

---

## 周期复盘建议

每 3 天或每周至少做一次汇总：

- 哪个来源端问题最多
- 哪个模块问题最多
- 哪个严重级别最多
- 哪些问题反复出现
- 哪些问题说明不是偶发，而是系统性缺口
