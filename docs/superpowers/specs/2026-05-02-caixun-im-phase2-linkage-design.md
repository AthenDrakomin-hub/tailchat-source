# 財訊 IM 第二阶段主场联动设计

## 1. 目标

在 Phase 1 已完成“动态一级入口 + 动态 MVP + 账号控制 facade 基础”的前提下，第二阶段不做分散加功能，而围绕一条主链路增强：

**动态发布 -> 导流到群 -> 群内互动 -> 账号接口可操控整条链路**

本阶段要同时增强三条线：

- 动态系统
- 主界面联动
- 账号控制接口

但三者必须围绕同一条可运营主链路展开，而不是各做各的。

## 2. 范围

### 2.1 动态系统增强

本阶段新增：

- 动态详情页
- 动态评论区
- 个人动态页
- 动态与群组关联信息强化
- 从动态进入群组 / 私聊的自然链路

### 2.2 主界面联动增强

本阶段增强：

- 动态页中更清晰的群组关联承接
- 群组页中更清晰的动态承接
- 会话流对活动/官方/服务型会话的轻量识别

### 2.3 账号控制接口增强

在 `openapi.account` 上扩展与主链路强相关的能力：

- 获取某账号动态列表
- 获取动态详情
- 发布动态
- 删除动态
- 评论动态
- 点赞动态
- 获取群列表
- 获取群详情
- 获取群公告
- 更新群公告
- 发群消息 / 私聊消息

## 3. 不在本阶段处理

- 推荐算法
- 动态富媒体重型能力
- 自动剧本编排系统
- 联系人全量自动化操作
- 大规模视觉重构

## 4. 设计原则

- 继续复用现有 Tailchat 结构，不做高风险推翻
- 保持“熟悉型 IM”主骨架
- 动态场更像财富论坛内容场，而不是朋友圈
- 所有接口命名继续保持“账号控制”语义，不引入 bot/robot 术语

## 5. 预期结果

完成后，`財訊 IM` 将从“已有动态入口和接口基础”，推进到“动态、群组、会话已经形成可被账号控制层驱动的可运营链路”。
