# 蓝图状态审计与后续方向说明

## 结论先看

当前项目**还没有进入蓝图的“Agent 社群操作系统”主线阶段**，目前真实落地的部分主要停留在：

1. 群消息发言治理
2. 群消息轻量角色识别
3. 群消息搜索上下文与发送反馈优化

也就是说，**现在更接近“群消息治理与阅读优化版 Tailchat”**，还**不是**蓝图里定义的：

- 一个群 = 一个自动化营销剧本单元
- 一个角色 Agent = 一个可复用运营资产
- 一个行业方案 = 一整套可复制模板
- 一个论坛 / 社区 = 最终沉淀与长期复利核心

## 状态总表

### A. 已完成，但只属于蓝图前置能力

#### 1. 群面板发言治理

已实现：
- 面板级 `speakPolicy` 数据结构
- 默认成员规则
- 角色规则
- Bot 规则
- 重复消息拦截
- 频率限制
- 快捷禁言入口

结论：
- 这是蓝图的“群剧本单元”前置基础设施
- 但它目前仍是**治理能力**，不是**剧本运营能力**

#### 2. 群消息轻量角色识别

已实现：
- 昵称颜色
- 头像环颜色
- 侧边色条

结论：
- 这是蓝图“角色人格在消息流中可见”的起点
- 但仍然只是**轻识别**，还没有进入你要的“角色气泡、人设风格、营销场域表现”

#### 3. 搜索上下文与发送反馈

已实现：
- 搜索结果加载附近消息上下文
- 目标消息高亮
- 输入区发送失败文案就地显示

结论：
- 这是群聊体验优化
- 对蓝图有辅助价值，但不是核心结构

---

### B. 已做但方向偏了，需要清理或弱化

#### 1. 机器人身份徽标

当前状态：
- 我上一轮增加了 `openapiBot -> 机器人`
- `pluginBot -> 插件`
- 在群聊昵称旁展示身份徽标

问题：
- 这会把产品方向继续往“区分是不是机器人”带
- 与你确认后的蓝图方向不一致
- 蓝图要突出的是“按群角色 / 角色人格表现消息”，不是“按技术身份贴标签”

处理建议：
- **删除这层默认展示**
- 后续改成“角色样式 / 人设徽标”
- 徽标来源应该是**群角色配置**，而不是 `user.type`

#### 2. 群面板编辑器里的“机器人规则”叙事权重过高

当前状态：
- 编辑器文案里仍强调“默认成员、角色与机器人的发言频率及消息识别样式”

问题：
- 会让产品继续围绕“机器人是特殊对象”设计
- 与“角色 Agent 资产”方向不一致

处理建议：
- 保留技术兼容字段，但**前台表达降级**
- 把产品叙事改成：
  - 角色发言治理
  - 角色消息表现
  - 角色型 Agent 的可视化人格

---

### C. 蓝图主线完全未开始

这几部分目前基本还是 **0 到 10%** 状态：

#### 1. 角色消息样式系统

当前：
- 只有昵称色 / 头像环 / 侧边色条

未做：
- 气泡背景色
- 气泡文字色
- 气泡边框色
- 角色徽标文本
- 角色徽标颜色
- 群角色层级统一配置入口

结论：
- **未进入蓝图目标形态**

#### 2. 系统级 Agent 总控后台

当前：
- 没有系统级 Agent 控制台
- 现有只有 OpenApp / Bot 应用面板

未做：
- Agent 定义
- 人格设定
- 运行模式
- 角色型资产管理
- 行业归属
- Prompt / Persona 管理

结论：
- **尚未开始**

#### 3. 群角色到 Agent 的绑定

当前：
- 没有群角色绑定 agent 的数据模型
- 没有群内角色到 agent 的控制入口

结论：
- **尚未开始**

#### 4. OpenClaw Bridge

当前：
- 项目内确认了 OpenAPI Bot / WS Bot 体系
- 也确认了 OpenClaw 可作为外部 gateway/runtime
- 但仓库里还没有真正 bridge 实现

结论：
- **概念和路线已确认，实现未开始**

#### 5. 剧本模板与论坛沉淀骨架

当前：
- 没有“群剧本单元”模型
- 没有“行业模板”模型
- 没有“论坛沉淀策略”接口

结论：
- **完全未开始**

当前进度：**15%**

- 发言治理存在

缺失：

- 周期阶段
- 触发条件
- 自动推进逻辑

已有：

- 消息轻识别存在

缺失：
- Agent 定义
- Persona
- 角色与 Agent 的一一映射
- 人设资产生命周期

### 蓝图层 3：行业模板

当前进度：**0%**

已有：
- 无成型结构

缺失：
- 行业模板模型
- 模板复制机制
- 模板与 Agent 组合关系

### 蓝图层 4：论坛 / 社区沉淀

当前进度：**5%**

已有：
- Tailchat 本身具备社区/消息基础

缺失：
- 论坛沉淀策略
- 群到论坛导流机制
- 内容 / 问答 / 人设沉淀模型

## 现在最明确的方向

后续必须按这个顺序推进，避免继续走偏：

### 第一步：先把“角色消息样式系统”做完整

目标：
- 让不同角色在消息流里真正形成人设区分

必须新增：
- 气泡背景色
- 气泡文字色
- 气泡边框色
- 角色徽标文本
- 角色徽标颜色

同时删除：
- 以 `user.type` 作为视觉身份主来源的做法

### 第二步：建立系统级 Agent 总控后台

目标：
- 把 Bot 从 OpenApp 的附属能力，升级为角色 Agent 资产

必须新增：
- Agent 定义
- Persona
- runtimeMode
- group/domain 可用范围
- 角色匹配关系

### 第三步：实现“群角色 -> Agent”绑定

目标：
- 让群角色真正驱动 agent 出场和剧本运转

### 第四步：接 OpenClaw Bridge

目标：
- 让 Tailchat 负责群与角色
- 让 OpenClaw 负责 Agent runtime

### 第五步：补“剧本模板 + 论坛沉淀”

目标：
- 让群从“会聊天”升级为“会按周期自动运转和沉淀”
