# Desktop 连续体验与 Web 会话主场设计

## 1. 目标

继续沿客户端优先路线推进，把“进入工作区”与“开始长期沟通”的连续体验再往前推一步。

本轮聚焦：

- `desktop` 从选择工作区到进入主窗口的连续感
- `web` 私信会话主场的信息层级再收口

## 2. 范围

### 2.1 Desktop 连续体验

增强 `client/desktop` 启动器：

- 点击工作区后显示明显的进入中状态
- 提示正在连接当前工作区
- 在进入过程中收紧可点击区域，避免像“点了没反应”

目标是让桌面端从启动器进入主窗口时更像真实客户端，而不是技术性跳转。

### 2.2 Web 会话主场

继续增强 `client/web` 私信会话主场：

- 会话头部表达更明确
- 消息区起始提示继续收口

目标是让私信场景看起来更像长期使用的 IM 主场。

## 3. 设计原则

- 不重做 desktop 主窗架构
- 不重做 web 聊天消息流
- 优先提升“点下去之后是否有连续反馈”的感知
- 保持低风险增量演进

## 4. 不在本轮处理

- Desktop 自动更新链
- Desktop 主窗原生侧边栏
- Web 多会话布局重构
- 桌面端原生通知设置面板

## 5. 预期结果

完成后：

- Desktop 从选择工作区到进入主窗的过程更可感知
- Web 私信会话更像可以长期使用的沟通面板
