# 最终客户端恢复体验收口设计

## 1. 目标

在当前客户端已具备入口、主路径、加载反馈和基础恢复能力的前提下，再完成最后一轮高频恢复体验收口。

本轮聚焦：

- `desktop` 主窗当前工作区操作
- `mobile` 恢复成功后的明确完成反馈节奏

## 2. 范围

### 2.1 Desktop 当前工作区操作

增强 `client/desktop`：

- 为主窗增加显式的当前工作区操作入口
- 支持在浏览器打开当前工作区
- 支持复制当前工作区地址
- 支持返回工作区选择

目标是让桌面端主窗更像真实客户端，而不是只能被动停留在当前工作区。

### 2.2 Mobile 恢复完成反馈节奏

增强 `client/mobile`：

- 仅在人工触发刷新或重试完成后，短暂显示明确成功反馈
- 首次正常加载不显示“恢复成功”
- 成功反馈结束后进入更稳定的连接状态文案

目标是让移动端恢复链路更像成熟产品，而不是把首次连接和恢复成功混为一谈。

## 3. 设计原则

- 不改变现有跨端主架构
- 不增加新的原生基础设施
- 优先提升恢复链路的连续感和完成感
- 保持低风险增量修改

## 4. 不在本轮处理

- Desktop 多工作区常驻切换器
- Mobile 原生 toast 系统
- Web 新一轮聊天主场大改

## 5. 预期结果

完成后：

- Desktop 用户可以在主窗中直接处理当前工作区相关动作
- Mobile 用户能明确感知“恢复已经成功完成”，且首次进入不会误报恢复成功
