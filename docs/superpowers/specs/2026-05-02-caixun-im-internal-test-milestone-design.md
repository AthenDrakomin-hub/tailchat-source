# 財訊 IM 可内测里程碑设计

## 1. 目标

将当前主线从“方向正确、链路可跑”推进到“可内测”状态。

所谓“可内测”，本阶段定义为：

- 用户进入产品后，能够清楚理解动态、群组、会话三者关系
- 动态详情到群承接更自然
- 会话列表已具备轻量角色识别
- 账号控制层已具备基于动态直接衔接到关联群动作的最小闭环
- 群运营摘要已提供更直接的信号字段，便于后续自动化运营与人工判断

## 2. 范围

### 2.1 群运营摘要信号增强

在 `openapi.account.getGroupOperationsSummary` 基础上继续补充：

- `hasRecentMessages`
- `isRecentlyActive`
- `activityStatus`

其中：

- `hasRecentMessages`：最近消息列表是否为空
- `isRecentlyActive`：是否在最近活跃时间阈值内
- `activityStatus`：`active` / `quiet`

### 2.2 动态到群的最小动作闭环

在 `openapi.account` 上增加：

- `sendFeedRelatedGroupMessage`

该动作接收：

- `postId`
- `content`

服务端内部自动：

- 读取动态详情
- 确认关联群
- 找到群大厅
- 发送消息

### 2.3 会话轻角色识别

在前台消息列表中，为明显的：

- 官方
- 服务
- 活动

类会话增加轻量标签识别。

识别策略保持克制，仅基于当前会话名称和已知模式做轻量呈现，不引入复杂后台配置。

### 2.4 动态详情承接收口

继续增强动态详情中的关联群卡片：

- 使用更直接的活跃状态文案
- 结合摘要信号给出“适合进入讨论 / 当前偏静态”的提示
- 收紧内容层级，使其更接近成品状态

## 3. 设计原则

- 可内测优先于功能铺满
- 只补最影响感知和链路闭环的能力
- 不引入后台系统和复杂配置中心
- 保持现有 Tailchat 结构增量演进

## 4. 不在本里程碑处理

- 后台运营面板
- AI 自动总结
- 推荐流
- 复杂风控审核体系
- 多维角色配置系统

## 5. 预期结果

完成后，`財訊 IM` 将达到：

- 主链路更清晰
- 群承接更可信
- 会话识别更像成品
- 账号控制层具备最小连续运营闭环

这将作为“可内测”阶段的完成标准。
