# Desktop 主动返回与 Mobile 恢复完成反馈设计

## 1. 目标

继续沿客户端优先路线推进，把恢复链路从“可用”推进到“更有连续感”。

本轮聚焦：

- `desktop` 主窗主动返回工作区选择
- `mobile` 恢复成功后的明确完成反馈

## 2. 范围

### 2.1 Desktop 主动返回

增强 `client/desktop`：

- 在主窗中增加返回工作区选择的入口
- 让用户不必等到错误时才能重新选择工作区

### 2.2 Mobile 恢复完成反馈

增强 `client/mobile`：

- 在刷新或重试完成后，短暂显示“已恢复”反馈
- 让恢复成功不只是状态文案变化，而是更可感知

## 3. 设计原则

- 不大改 desktop 菜单体系
- 不改变 mobile WebView 架构
- 优先提升主动作和恢复完成感
- 保持低风险增量实现

## 4. 不在本轮处理

- Desktop 多工作区常驻切换器
- Mobile 原生 toast 基础设施
- Web 本轮新增主路径
- Desktop 托盘和系统级状态

## 5. 预期结果

完成后：

- Desktop 用户可以从主窗主动回到工作区选择
- Mobile 在恢复成功后有更明确的完成感
