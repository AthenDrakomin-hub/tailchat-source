# Desktop 失败恢复与 Mobile 刷新一致性设计

## 1. 目标

继续沿客户端优先路线推进，把“失败后怎么办”和“恢复是否一致”这两个高频体验补完整。

本轮聚焦：

- `desktop` 主窗加载失败后的恢复动作
- `mobile` 刷新、重试和恢复动作的一致性

## 2. 范围

### 2.1 Desktop 失败恢复

增强 `client/desktop` 主窗口加载失败场景：

- 明确提供“重试”动作
- 明确提供“返回工作区选择”动作
- 避免用户只能看到失败标题却不知道下一步怎么做

### 2.2 Mobile 刷新一致性

增强 `client/mobile` 当前工作区容器：

- 将刷新、重试统一为同一套恢复流程
- 统一重置加载、错误和状态文案
- 在恢复时给出一致的反馈

## 3. 设计原则

- 不引入新的桌面复杂面板系统
- 不改变 mobile WebView 核心架构
- 优先提升失败后的可恢复性
- 保持增量实现

## 4. 不在本轮处理

- Desktop 离线页
- Desktop 多工作区切换器
- Mobile 原生网络状态监听
- Web 本轮新增功能

## 5. 预期结果

完成后：

- Desktop 主窗加载失败时，用户能直接选择重试或返回选择工作区
- Mobile 刷新和重试表现一致，不同入口触发时反馈更统一
