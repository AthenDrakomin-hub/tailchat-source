# 客户端主路径收口设计

## 1. 目标

在完成客户端入口层收口后，继续把用户进入产品后的主路径做得更像真实可用客户端。

本轮聚焦两个最关键的平台：

- `web`
- `mobile`

## 2. 范围

### 2.1 Web 端主路径收口

在当前 Web 主结构不大改的前提下，优先增强最常见的“第一屏感知”：

- 动态首页顶部增加更像成品的主路径引导卡片
- 群组总览页不再只是简单 `Problem`，而是给出“下一步做什么”的引导
- 提醒/通知页在未选中状态下给出更明确的解释与建议

目标是让第一次进入 `web` 主界面的用户，不会只看到空白或单句提示，而能理解当前应该怎么开始使用。

### 2.2 Mobile 端主路径收口

在移动端当前 `WebView` 架构不变的前提下，增强进入后的原生壳体验：

- 为 `AppMain` 增加顶部原生栏
- 顶部栏展示当前工作区名称
- 提供切换工作区入口
- 提供页面刷新能力

目标是让移动端进入后不再像“只打开了一个网页”，而是更像有原生导航感的客户端容器。

## 3. 设计原则

- 不改底层跨端架构
- 优先提升第一屏理解成本
- 优先增强用户对“下一步做什么”的感知
- 维持当前代码结构的增量演进

## 4. 不在本轮处理

- 移动端完整原生底部导航
- Web 端大规模布局重构
- 桌面端深层能力（通知、窗口、多实例）
- 商城提审能力

## 5. 预期结果

完成后：

- Web 端主界面更像成品，不会在关键未选择状态下显得过空
- Mobile 端进入后的主路径更像真实客户端，而不是单纯 WebView 外壳
