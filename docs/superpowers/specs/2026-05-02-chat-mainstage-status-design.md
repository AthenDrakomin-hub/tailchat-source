# 聊天主场与状态反馈设计

## 1. 目标

继续沿客户端优先路线推进，把聊天使用体验再往“长期使用的客户端”推进一步。

本轮聚焦：

- `web` 私信会话主场的信息层级
- `mobile` 当前工作区页面状态的持续反馈

## 2. 范围

### 2.1 Web 聊天主场

增强 `client/web` 私信聊天主场：

- 会话头部补充更清楚的辅助说明
- 空会话聊天第一屏继续收口为更像长期使用 IM 的起始页

目标是让用户进入私信会话时，不只是看到标题和输入框，而能更清楚理解当前会话的性质与下一步动作。

### 2.2 Mobile 状态反馈

增强 `client/mobile` 当前工作区壳层反馈：

- 当工作区页面恢复加载时，给出更明确状态变化
- 当页面进入服务异常 / 慢网络场景时，给出更易理解提示

目标是让移动端容器更接近真实 App 的状态反馈，而不是只停留在基础加载与失败提示。

## 3. 设计原则

- 不重做聊天主布局
- 不引入新原生网络库
- 优先提升高频使用时的感知质量
- 保持现有结构增量演进

## 4. 不在本轮处理

- 消息列表完整重设计
- 移动端原生消息页
- 离线缓存
- Web 多会话视图

## 5. 预期结果

完成后：

- Web 私信会话会更像主产品场景，而不是技术面板
- Mobile 会更清楚地反馈页面当前所处状态
