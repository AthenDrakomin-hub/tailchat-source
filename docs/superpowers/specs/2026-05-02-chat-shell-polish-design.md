# 会话主路径与移动壳层优化设计

## 1. 目标

继续沿客户端优先路线推进，重点解决：

- `web` 私信 / 联系人主路径仍然偏空、偏弱的问题
- `mobile` 虽然已有顶部栏，但进入后仍然缺少返回、加载与异常反馈

## 2. 范围

### 2.1 Web 会话主路径

增强 `client/web` 的个人消息主路径：

- 当最近聊天为空时，侧栏显示明确的空状态引导
- 联系人页顶部增加更像成品的说明卡片
- 帮助用户理解“先加联系人，再开始会话”的路径

### 2.2 Mobile 壳层能力

增强 `client/mobile` 的 `AppMain`：

- 增加返回能力
- 增加页面加载反馈
- 增加错误状态提示
- 增加重试动作

目标是让移动端 `WebView` 外壳不再像“打开网页”，而更像具备基础原生导航与反馈的客户端容器。

## 3. 设计原则

- 不大改聊天架构
- 优先解决主路径感知问题
- 优先补齐原生容器最基础但最关键的反馈
- 继续保持低风险增量修改

## 4. 不在本轮处理

- Web 会话区完整重设计
- Mobile 原生底部标签栏
- Push、后台保活、深链跳转
- 聊天列表算法与推荐排序

## 5. 预期结果

完成后：

- Web 私信 / 联系人主路径更容易上手
- Mobile 进入后的主路径更稳定、反馈更完整
