# 財訊客户端可用性里程碑设计

## 1. 目标

将当前工作重心从服务端接口继续扩展，切换到用户真正感知的客户端完善。

本里程碑聚焦三个直接面向用户的平台：

- `web`
- `desktop`
- `mobile`

并同步完善官网 `downloads` 页面，使后续向桌面安装和手机商城上架推进时，已有更可信的客户端入口表达。

## 2. 范围

### 2.1 Web 端

在 Web 登录入口增加更清晰的客户端导流信息：

- Web 在线使用说明
- 桌面端与移动端入口提示
- 当前阶段为“可内测”的说明

目标是让首次进入产品的用户知道：

- 现在可以直接使用 Web
- 也可以下载桌面端或继续关注移动端
- 当前版本定位是内测阶段，而非正式全面发布

### 2.2 Desktop 端

将当前桌面端启动器从通用 Tailchat 壳表达，收口为更明确的財訊桌面客户端入口：

- 强化品牌语义
- 强化推荐服务器/工作区提示
- 强化“桌面端适合长期使用”的文案

### 2.3 Mobile 端

将当前移动端服务器入口页从技术性选择页，收口成更像真实移动客户端入口：

- 更清楚的品牌说明
- 更清楚的测试状态说明
- 更清楚的服务器选择/添加引导
- 更适合窄屏用户理解的入口层级

### 2.4 官网下载页

将官网 `downloads` 页面从测试性文案，收口成更像真实分发页：

- 明确 Web / Desktop / Mobile 的当前状态
- 强调当前优先推荐的使用方式
- 强化后续 App Store / Android 商店上架准备方向

## 3. 设计原则

- 优先做“用户第一眼能感知到”的客户端体验
- 不在本轮引入复杂原生能力开发
- 保持现有结构增量演进
- 以“可内测可理解”为标准，而不是一次性追求正式发布

## 4. 不在本轮处理

- iOS / Android 商店正式提审材料
- 推送、原生通知、后台保活等深层移动能力
- 桌面端自动更新链
- 多平台统一安装器体系

## 5. 预期结果

完成后，项目会达到以下状态：

- Web 登录入口更清楚地承担主入口角色
- Desktop 启动器更像財訊桌面客户端，而不是技术壳
- Mobile 入口页更像真实 App 入口，而不是技术配置页
- 官网下载页更适合给内部测试用户理解与分发
