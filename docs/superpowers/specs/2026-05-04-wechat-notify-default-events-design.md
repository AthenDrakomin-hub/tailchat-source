# 财讯微信通知默认事件收敛设计

## 背景

上一轮已经实现了微信通知绑定、解绑、测试通知、用户偏好与 `@你` / 私聊提醒。

但从产品角度看，这一版对普通用户仍然过重：

- 客户端出现了通知类型选择
- 客户端出现了测试通知按钮
- 推送规则更像配置系统，而不是默认产品能力

财讯当前更适合“前台简单、后台配置”的方案。

## 目标

把微信通知收敛成默认能力：

1. 客户端不再提供通知类型选择
2. 客户端不再提供测试通知按钮
3. 客户端只保留绑定状态、授权、解绑和固定说明
4. 服务端默认只推送三类事件：
   - 好友私信
   - 语音电话来电
   - 群组 `@所有人`
5. 测试与具体配置保留在后台能力层

## 方案

### 客户端

微信通知页只展示：

- 绑定状态
- 去授权
- 解除绑定
- 固定规则说明

固定文案明确告知：

- 好友私信会微信提醒
- 语音电话来电会微信提醒
- 群组 `@所有人` 会微信提醒

### 服务端

服务端不再依据客户端偏好字段判断是否推送，而是使用固定默认规则：

- `directMessage`
- `voiceCall`
- `mentionAll`

仍然保留免打扰校验：

- 私聊会话被静音则不推
- 群组被静音则不推

### 语音电话事件

`com.msgbyte.livekit` 已有真实来电入口：

- `inviteCall` action
- `plugin:com.msgbyte.livekit.inviteCall` socket 通知

本次应在服务端 `inviteCall` action 内同时触发微信提醒，而不是依赖前端弹窗。

### 群组 `@所有人`

当前仓库没有稳定的 `mentionAll` 字段，因此本次以最小可行方案实现：

- 当群消息 `plain/content` 中包含 `@所有人` 或 `@all`
- 视为群组全体提醒
- 推送给除发送者外的群成员

## 非目标

- 不恢复客户端通知偏好开关
- 不在客户端保留测试通知按钮
- 不扩展到更多通知种类

## 验收标准

1. 客户端微信通知页不再出现偏好开关
2. 客户端微信通知页不再出现测试通知按钮
3. 客户端明确展示三类默认通知
4. 私聊新消息可触发微信提醒
5. LiveKit 来电邀请可触发微信提醒
6. 群消息包含 `@所有人` 或 `@all` 可触发微信提醒
