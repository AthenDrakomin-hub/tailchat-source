# 财讯微信通知授权与后台插件中心设计

## 背景

财讯客户端当前已经明确不再向普通用户暴露“插件中心”产品面，但这不意味着插件体系不再重要。相反：

- 普通用户前台不应该理解插件
- 管理后台必须保留插件可见性，便于运营查看、启用和筛选可用能力
- 消息通知能力需要先快速落地一个可运行闭环

结合现有仓库内容，可以确认两件事：

1. 项目历史文档中明确存在 `com.msgbyte.wxpusher` 的能力说明，且文档声明支持“微信扫码绑定账号后，@你 的消息自动在微信中推送”
2. 当前管理后台已有一个较原始的 `plugin-permissions` 页面，可以读取 `/registry-be.json`，但还不是一个面向运营的插件中心总览

因此，本次设计采用：

- 前台增加“微信通知授权”产品入口
- 底层使用 `WxPusher/第三方` 通道
- 管理后台恢复并加强插件中心可见性
- 客户端继续不暴露“插件中心”概念

## 目标

本次要完成的 5 项目标：

1. 管理后台恢复插件中心可见性，并能查看可用插件
2. 管理后台可清楚看到 `wxpusher` 是否可用以及如何配置
3. 客户端增加“微信通知授权”入口
4. 服务端增加 WxPusher 绑定状态、授权链接、解绑、回调链路
5. 打通“收到 @你 的消息 -> 微信推送提醒”的最小闭环

## 非目标

本次不做：

- 全量消息推送
- 群消息全量推送
- 多通道切换
- 复杂免打扰规则
- 用户前台插件市场恢复
- 与公众号模板消息/企业微信同时接入

## 方案

### 1. 前台产品形态

普通用户看到的是：

- 微信通知
- 去绑定
- 已绑定微信
- 解除绑定

普通用户看不到的是：

- 插件中心
- wxpusher
- 第三方插件配置细节

推荐入口位置：

- 客户端设置中的“服务与支持”或“偏好设置”下新增“微信通知”

### 2. 服务端数据模型

新增一个轻量绑定模型，例如：

- `userId`
- `wxpusherUid`
- `wxpusherExtra`（可选）
- `enabled`
- `createdAt`
- `updatedAt`

该模型只服务于推送绑定关系，不侵入用户基础资料结构。

### 3. 服务端接口

新增一组服务端接口：

- 获取微信通知绑定状态
- 生成授权链接
- 接收绑定回调
- 解绑微信通知
- 发送测试通知（可选，仅后台/调试用）

接口设计原则：

- 客户端只拿到“状态”和“授权链接”
- 不需要理解第三方实现细节

### 4. 推送触发规则

第一版仅做：

- 当消息明确 `@` 到当前用户时
- 若该用户已绑定微信通知
- 则向其推送一条微信提醒

提醒内容应包含：

- 发送者昵称
- 消息摘要
- 来源场景（群/私聊）

### 5. 管理后台插件中心

管理后台新增或升级为“插件中心”页面：

- 从 `/registry-be.json` 读取插件列表
- 展示插件名、中文名、版本、描述
- 增加“是否内置 / 是否可能用于财讯”的可读状态
- 如果检测到 `wxpusher` 不在当前注册表中，要明确提示“当前构建未包含 wxpusher”

这样你可以在后台自己查看哪些插件可用，而客户端继续不暴露插件概念。

## 风险与约束

### 风险 1：仓库中未包含 `com.msgbyte.wxpusher` 插件源码

当前仓库可以确认有文档和开放接口描述，但未在 `server/public/plugins` 或 `server/plugins` 目录中直接发现源码或构建产物。

因此本次实现采用“双层兼容”：

- 若环境中真实存在 `wxpusher` 插件，则优先走插件能力
- 若当前构建未包含插件，则使用财讯内置的兼容绑定与推送实现

### 风险 2：消息触发点较多

第一版只接 `@你` 提醒，避免过早扩散。

### 风险 3：客户端设置入口位置过深

第一版先放在设置页，后续如果需要再上移到资料页。

## 验收标准

满足以下条件即可视为本次完成：

1. 管理后台能看到插件中心总览页
2. 插件中心能展示当前注册表中的插件清单
3. 客户端设置中能看到“微信通知”入口
4. 用户能看到绑定状态，并能点击授权/解绑
5. 服务端存在绑定状态接口、授权链接接口、解绑接口
6. `@你` 消息触发推送时，逻辑已接入绑定检查与推送发送
7. 前端类型检查和服务端类型检查通过

## 最终结论

本次采用：

- **前台做财讯原生“微信通知授权”**
- **底层兼容复用 WxPusher 通道**
- **后台恢复插件中心可见性**
- **第一版只打通 @你 消息微信提醒**

这是当前最快、最稳、最符合财讯产品边界的实现路径。
