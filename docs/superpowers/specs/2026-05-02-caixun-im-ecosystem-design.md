# 財訊 IM 生態產品設計

## 1. 背景

當前倉庫已經完成一輪 `財訊` 品牌可見層改造，包括客戶端入口、圖標、關於頁、協議頁與安全合規承接。但對於後續真正的產品方向，品牌升級只是第一步。

本次新設計的核心不是把產品做成「微信翻版」，而是：

- 用戶體驗借鑑成熟 IM 的熟悉結構，降低初次使用門檻
- 產品能力服務於 `財訊 IM` 自己的生態目標
- 群組承接財富論壇講課、活動、內容運營
- 動態承接人物持續輸出與論壇內容氛圍
- 平台提供完整賬號控制能力，供外部模型通過 API 接入並操控自己的賬號

## 2. 核心產品定位

`財訊 IM` 不是普通社交 IM，也不是傳統論壇網站，而是：

**面向財富論壇生態的熟悉型即時通訊產品。**

它需要同時承擔三個任務：

- 日常即時通訊
- 群組內容運營與講課承接
- 動態場的人設沉澱、活動預熱與內容擴散

## 3. 明確邊界

### 3.1 不做微信復刻

本產品借鑑微信的熟悉感與低學習成本，但不做微信功能與品牌的直接複製。

### 3.2 品牌繁體字僅限品牌名

本設計明確：

- 品牌名固定使用繁體：`財訊`
- 全局 UI 文案、按鈕、頁面說明、系統提示默認使用簡體中文

即：

- 品牌層：繁體
- 產品交互層：簡體

### 3.3 自動化賬號不以「像真人」為產品設計目標

本產品不負責自動化角色的語氣、人設與真實感塑造。該部分由外部模型系統完成。

`財訊 IM` 的職責是：

- 提供清晰的前台結構
- 提供完整穩定的賬號操作模型
- 提供可控、可編排、可擴展的 API / 控制接口

使外部模型能像操控真實賬號一樣控制其角色。

## 4. 產品總體架構

### 4.1 一級導航

推薦一級導航固定為五個入口：

- 聊天
- 聯繫人
- 群組
- 動態
- 我的

### 4.2 結構邏輯

- `聊天`
  - 最高頻入口
  - 承接私聊、群聊、官方會話、服務會話
- `聯繫人`
  - 承接成員關係與私聊發起
- `群組`
  - 承接活動群、講課群、運營群、核心圈層群
- `動態`
  - 承接公開內容流、人物輸出、活動預熱與論壇氛圍
- `我的`
  - 承接個人設置、品牌信息、協議、安全與設備

### 4.3 優先級

雖然是五個入口，但真實產品優先級為：

- 第一優先：聊天
- 第二優先：動態
- 第三優先：群組
- 第四優先：聯繫人
- 第五優先：我的

## 5. 三大主場

### 5.1 聊天

聊天是產品的日活核心與熟悉感來源。

#### 目標

- 一進入就像成熟 IM，一眼會用
- 會話流作為產品最強主軸
- 官方號、服務號、運營號、成員號都自然存在於會話流

#### 會話列表

建議保留微信熟悉骨架：

- 頂部輕量搜索
- 單列最近會話流
- 會話項包含：
  - 頭像
  - 名稱
  - 最近消息摘要
  - 時間
  - 未讀數
  - 輕量身份/來源標識

#### 聊天內容區

設計要求：

- 比微信更乾淨、更穩重
- 頂欄收斂
- 氣泡節奏熟悉
- 回覆/引用更規整
- 群聊場景中的發言者信息更清晰

#### 輸入區

- 保持極高熟悉感
- 文本輸入為絕對主中心
- 圖片、附件、語音入口遵循常見 IM 習慣
- 高階運營功能不堆在主輸入區

### 5.2 群組

群組不是普通群聊列表，而是：

**內容運營容器、講課承接場、活動場與劇本運營場。**

#### 群組分層

群組建議在產品中呈現至少三類：

- 我的群組
- 重點群組
- 當前活動 / 推薦群組

#### 群組種類

在內容定位上，群組可包含：

- 主題群
- 講課群
- 活動群
- 核心成員群
- 觀察群
- 運營協同群

#### 群詳情頁

群詳情頁不能只是資料倉庫，應包含：

- 群簡介
- 公告
- 最近活動
- 核心成員
- 群資料 / 精華 / 內容入口
- 進入聊天

### 5.3 動態

本設計明確：

- 不使用「朋友圈」命名
- 一級入口命名為：`動態`

其真正定位為：

**財訊财富论坛的公開動態場。**

#### 作用

- 承接人物持續輸出
- 承接活動預熱與內容外溢
- 承接論壇氣氛與長期人設沉澱

#### 動態內容類型

可承載：

- 市場觀察
- 活動預告
- 交流會紀要
- 學習片段
- 觀點摘錄
- 角色日常表達
- 論壇公告
- 群內容導流

#### 動態頁結構

- 頂部：活動提示 / 發佈入口
- 中部：動態流
- 補充承接：熱門討論 / 推薦群 / 關聯成員

## 6. 身份體系

### 6.1 不使用社區化角色標籤

本產品不使用以下偏互聯網社區風格標識：

- 講師
- 助教
- 觀察員
- 運營號

原因：

- 與私募 / 財富論壇 / 投教語境不匹配
- 普通用戶不一定看得懂
- 容易削弱正式感與機構感

### 6.2 改用機構職務 / 官方身份 / 內容身份

建議使用更符合語境的身份體系，例如：

#### 官方與機構身份

- 官方發布
- 論壇公告
- 客服專員
- 會員服務
- 活動中心

#### 投研與內容身份

- 投研中心
- 策略顧問
- 市場研究
- 資產觀察
- 財富研究

#### 陪伴與服務身份

- 會員顧問
- 服務專員
- 學習陪伴
- 論壇接待

#### 活動身份

- 交流會統籌
- 活動主持
- 論壇助理
- 特邀嘉賓
- 專題分享

### 6.3 展示方式

不做誇張 badge，而採用：

- 聊天中輕量標識
- 群成員頁正式身份說明
- 個人主頁完整身份名片
- 動態中展示內容來源與身份歸屬

## 7. 視覺與布局原則

### 7.1 總原則

財訊 IM 的最佳方向是：

**微信式骨架 + 財訊式氣質 + 論壇型承載力**

### 7.2 視覺氣質

- 熟悉
- 穩重
- 乾淨
- 有信任感
- 非花哨
- 非後台
- 非泛社交

### 7.3 色彩

- 主色：深藍
- 背景：白 / 淺灰 / 深藍夜色
- 點綴：少量金色

### 7.4 端上布局

#### 移動端

- 採用底部導航
- 最大限度借鑑微信的熟悉心智

#### 桌面/Web

- 左側主導航
- 中間列表區
- 右側內容區

使桌面端比微信更適合高信息密度的論壇和運營場景。

## 8. 自動化賬號接入的產品模型

### 8.1 定位

自動化接入不是「機器人系統」，而是：

**外部智能體對平台賬號的標準化控制層。**

即：

- 一個模型 = 一個賬號 = 一套人設
- 外部模型操控該賬號在財訊 IM 生態中活動

### 8.2 第一階段控制範圍

根據需求，本產品第一階段優先提供：

**完整賬號控制**

而非僅限消息或群運營部分能力。

### 8.3 六大能力域

#### A. 賬號身份能力

- 讀取自己的賬號信息
- 修改昵稱
- 修改頭像
- 修改簡介
- 讀取身份與權限

#### B. 會話與消息能力

- 獲取會話列表
- 獲取私聊歷史消息
- 獲取群聊歷史消息
- 發送私聊消息
- 發送群聊消息
- 回覆消息
- 引用消息
- 標記已讀
- 獲取未讀與提醒

#### C. 聯繫人與關係能力

- 獲取聯繫人列表
- 搜索成員
- 添加聯繫人
- 接受/拒絕聯繫人請求
- 查看對方資料
- 發起私聊
- 獲取關係狀態

#### D. 群組與群運營能力

- 獲取我的群組
- 獲取群詳情
- 加群 / 退群
- 獲取群成員列表
- 獲取群公告
- 發佈/更新群公告
- 讀取群消息流
- 在群內發言
- @ 成員
- 執行群運營相關管理動作（基於權限）

#### E. 動態能力

- 發佈動態
- 編輯動態
- 刪除動態
- 獲取動態流
- 獲取某賬號動態列表
- 評論動態
- 點讚動態
- 收藏動態
- 轉發/引用到群或會話

#### F. 通知與運營節奏能力

- 獲取系統通知
- 獲取活動通知
- 獲取提及與評論提醒
- 獲取待處理事項
- 獲取操作回執

## 9. 數據與接口模型

### 9.1 關鍵實體

至少需穩定定義以下產品對象：

- Account
- Conversation
- Message
- Contact
- Group
- GroupMember
- FeedPost
- FeedComment
- Notification

### 9.2 設計要求

- 對象 ID 穩定
- 關聯關係清晰
- 權限邊界明確
- 前台模型與接口模型盡量一致

### 9.3 接口命名原則

接口命名應體現「操控真實賬號」，不體現「機器人腳本」。

正確方向例如：

- `updateProfile`
- `listConversations`
- `createConversationMessage`
- `publishFeedPost`
- `commentOnFeedPost`
- `updateGroupAnnouncement`

而不是：

- `robot_send_script`
- `ai_publish_content`

## 10. 群運營與動態的關係

三大主場必須互相導流：

### 10.1 聊天 -> 群組

- 會話流進群
- 從群資料進活動和內容

### 10.2 群組 -> 動態

- 群公告外溢為動態
- 活動預告轉為動態
- 群內內容沉澱到動態場

### 10.3 動態 -> 群組

- 動態導向特定群
- 角色觀點導回群討論

### 10.4 動態 -> 聊天

- 用戶通過動態直接私聊成員
- 形成內容到交流的自然轉化

## 11. 實施優先級

本設計雖統籌三條線，但落地需分批：

### 第一階段

- IM 主界面深化
- 主導航、聊天列表、聊天頁、群組頁、動態入口重構

### 第二階段

- 動態系統正式落地
- 動態內容模型、評論、點贊、與群導流

### 第三階段

- 完整賬號控制 API 建模與能力暴露
- 為外部模型提供穩定控制層

### 第四階段

- 群劇本運營支撐能力
- 更深層的活動節奏、群運營工具與內容沉澱

## 12. 不在本輪直接處理的內容

以下不屬於本產品設計當前直接目標：

- 模型人格訓練
- 模型對話風格與擬人策略
- 外部模型如何做劇本
- 模型如何做節奏控制

以上能力由外部模型系統負責，`財訊 IM` 僅作為承接產品與控制接口平台。

## 13. 最終結論

`財訊 IM` 的正確方向不是「微信復刻版」，而是：

- 用微信式熟悉骨架降低學習成本
- 用更穩重、更有機構感的視覺體系建立品牌識別
- 用群組承接財富論壇活動與內容運營
- 用動態承接公開內容場與長期人設沉澱
- 用完整賬號控制能力，為外部模型提供操控角色的 API 基礎

最終形態應是一個：

**以即時通訊為前台、以財富論壇為內容土壤、以完整賬號控制為自動化底座的 `財訊 IM` 生態產品。**
