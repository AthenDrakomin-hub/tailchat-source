# Web 试运营上线清单

## 目标

这份清单用于判断当前 `Web` 端是否可以正式进入试运营，并指导上线前、上线当天、首周观察期的执行动作。

适用范围：

- Web 作为主试运营入口
- Desktop 作为辅助体验端
- Mobile 暂不作为主承接端

当前判断基线：

- 代码与界面主链路已经具备试运营基础
- 本清单重点覆盖“能否上线”和“上线后如何控风险”

---

## Go / No-Go 标准

### 可以进入试运营

满足以下条件即可进入小范围试运营：

- `P0` 项全部满足
- `P1` 项大部分满足，且不存在影响主链路的已知阻断问题
- 上线当天有人值守
- 首周有明确的问题收集与回收机制

### 不可以进入试运营

出现以下任一情况，不建议上线：

- 登录、进入主界面、群组、私信四条主链路任一不可用
- 状态页显示基础服务异常且无法短时间恢复
- 已知存在高频白屏、无法发送消息、无法进入群组等主路径阻断
- 没有值守、没有问题登记方式、没有停运条件

---

## P0 必过项

以下项目是上线前必须全部通过的。

### 1. 基础访问

- [ ] Web 站点可正常打开
- [ ] 登录页可正常进入
- [ ] 登录成功后可稳定进入主界面
- [ ] 刷新页面后会话状态正常，不出现无限跳转或反复登录

### 2. 主路径可用

- [ ] 可以进入动态页，并能正常查看内容流
- [ ] 可以进入群组总览，并能进入至少一个群组
- [ ] 可以进入联系人页，并能看到联系人相关区域
- [ ] 可以进入私信会话，并能发送至少一条文本消息
- [ ] 会话空状态、聊天输入区、最近聊天承接正常

### 3. 试运营承接页可用

- [ ] 设置中的“状态”页能正常打开
- [ ] 状态页能展示服务健康度、可用服务数、建议动作
- [ ] 关于页能正常打开
- [ ] 关于页中试运营帮助入口可见
- [ ] 联系人页中的试运营起步面板可见

### 4. 风险与信任基础

- [ ] 关于页中的“关于我们”入口可打开
- [ ] “安全与合规”入口可打开
- [ ] 客户端下载说明入口可打开

### 5. 工程基线

- [ ] `client/web check:type` 通过
- [ ] 整仓 `pnpm build` 通过
- [ ] 当前主线代码已推送并可回滚到稳定提交

---

## P1 建议满足项

这些不是绝对阻断项，但强烈建议在试运营开始前具备。

### 1. 运营准备

- [ ] 准备一份试运营说明，告诉用户当前是试运营版本
- [ ] 准备一份用户反馈入口，例如群、表单、工单或统一联系人
- [ ] 准备一份常见问题答复模板

### 2. 值守准备

- [ ] 明确上线当天值守人员
- [ ] 明确问题分级人
- [ ] 明确谁可以执行“暂停试运营”决定

### 3. 试运营样本准备

- [ ] 准备至少 10 到 30 位真实试运营用户
- [ ] 确保这些用户至少覆盖动态浏览、群组讨论、私信沟通三类行为
- [ ] 至少准备 2 到 3 个真实群组场景

---

## 可延期项

这些项不应阻止当前 Web 端进入小范围试运营，但要在后续迭代中补齐。

- [ ] 更完整的数据看板
- [ ] 更系统的用户行为埋点
- [ ] 更细的浏览器兼容性矩阵
- [ ] 更完整的运营后台能力
- [ ] 更标准化的公告 / 帮助中心体系

---

### 对外准备

## 首周观察项

首周不追求“没有问题”，追求“快速知道问题在哪里”。

### 每日必须看

- [ ] 登录是否稳定
- [ ] 动态页是否稳定打开
- [ ] 群组页是否稳定打开
- [ ] 私信发送是否稳定
- [ ] 状态页是否出现基础服务异常

### 每日必须收集

- [ ] 用户最常卡在哪一步
- [ ] 用户最常问的 3 个问题是什么
- [ ] 是否有人因为找不到入口而中断使用
- [ ] 是否有人因为状态不明确而误以为系统故障

### 每日必须输出

- [ ] 当日新增问题数
- [ ] `P0` 问题数
- [ ] `P1` 问题数
- [ ] 是否继续放量

## 问题分级建议

### P0

立即处理，必要时暂停试运营：

- 无法登录
- 无法进入主界面
- 无法进入群组
- 无法发送私信
- 状态页显示基础服务大面积异常

### P1

当天处理或当天给出替代方案：

- 某个入口不清楚
- 某个页面文案误导
- 某类操作反馈不明确
- 某些用户路径需要人工说明才能继续

### P2

进入后续迭代：

- 样式细节
- 排版优化
- 更丰富的帮助文案
- 更完整的辅助说明

---

## 停运条件

满足以下任一条件，建议暂停试运营或停止继续放量：

- 连续出现主路径不可用问题
- 登录或聊天出现高频阻断
- 用户反馈已经从“可接受问题”升级成“无法继续使用”
- 状态中心显示基础服务异常且短时间无法恢复
- 值守人员无法及时响应

---

## 当前建议结论

基于当前仓库状态，我建议：

- Web 端可以进入小范围试运营
- 首批人数控制在 `10 到 30` 人
- 先验证 `动态 / 群组 / 私信` 三条主链路
- 试运营首周按本清单逐日记录问题，不要一开始就大规模公开放量

---

## 执行顺序

如果你要今天开始推进，建议直接按这个顺序执行：

1. 完成 `P0` 检查
2. 完成上线前一天清单
3. 准备用户名单和反馈入口
4. 小范围开放试运营
5. 连续观察一周
6. 一周后决定是否扩大范围
