# 群组内容语法说明

## 先说结论

如果你想在群组里做一份“公告 / 说明页 / 长文内容”，**不要按 HTML 页面去写**。

当前项目里和群组内容相关的几种编辑入口，支持的语法并不一样：

1. 群组基础说明 `description`
   - 普通文本
   - 不是 Markdown 编辑器
   - 不是 HTML 编辑器

2. 欢迎词插件 `com.msgbyte.welcome`
   - 普通文本框
   - 不是 HTML
   - 支持少量占位符

3. 真正适合写“公告/说明”的入口
   - `Markdown Panel`
   - 使用 Markdown 语法，不是自由 HTML

## 一、群组基础说明

群组基础说明来自群组字段：

- `description`

它在服务端允许修改，但本质上只是一个字符串字段。当前仓库里没有把它当作 HTML 公告页来编辑或渲染的实现。

所以建议把它理解为：

- 简短说明
- 群简介
- 一两句话的文本备注

不建议把它当成：

- 富文本公告
- 可排版 HTML 页面
- 图文混排说明页

## 二、欢迎词插件

欢迎词插件来自：

- `server/plugins/com.msgbyte.welcome`

它的群组配置项 `groupWelcomeText` 使用的是普通 `TextArea`，不是 MarkdownEditor。

### 支持的内容

- 普通文本
- 换行
- 字符数限制内的说明文字

### 支持的占位符

- `{nickname}`
  - 替换为新成员昵称
- `{@nickname}`
  - 替换为可 @ 的新成员内容

### 示例

```text
欢迎 {nickname} 加入本群
```

```text
欢迎 {@nickname} 加入本群，请先阅读群规
```

### 不建议期待的能力

- 不要按 HTML 写
- 不要按 Markdown 富文本写
- 不要期待自定义样式

## 三、真正适合做公告的是 Markdown Panel

如果你要写的是：

- 群公告
- 群介绍页
- 入群说明
- 长文排版
- 图文混合内容

应优先使用：

- `com.msgbyte.mdpanel`

对应实现位于：

- `client/web/plugins/com.msgbyte.mdpanel`

它使用的编辑器是：

- `MarkdownEditor`

它使用的渲染器是：

- `Markdown`

## 四、Markdown Panel 支持什么语法

根据当前实现，它的核心能力是：

- 基于 Markdown
- 启用 GFM 扩展

### 你可以安全使用的语法

- 标题
- 段落
- 列表
- 引用
- 粗体 / 斜体
- 链接
- 图片
- 表格
- 代码块
- 行内代码
- 任务列表（取决于 GFM 渲染效果）

### 示例

#### 标题和段落

```md
# 群公告

欢迎加入本群，请先阅读以下内容。
```

#### 列表

```md
## 群规

- 禁止广告
- 禁止刷屏
- 禁止发布违法违规内容
```

#### 链接和图片

```md
[访问官网](https://example.com)

![公告配图](https://example.com/banner.png)
```

#### 表格

```md
| 项目 | 说明 |
| --- | --- |
| 入群规则 | 先看公告 |
| 联系方式 | 管理员私聊 |
```

#### 代码块

```md
```bash
docker compose ps
```
```

## 五、不建议使用的语法

### 1. 不要把它当成通用 HTML 编辑器

虽然渲染链中存在 `rehypeRaw` / `sanitize` / `iframe` 相关逻辑，但当前实现同时设置了：

- `skipHtml={true}`

并且组件明确对这些元素给出“不支持”提示：

- `html`
- `style`
- `meta`
- `embed`

所以在实际使用中，最安全的理解是：

- **按 Markdown 用**
- **不要依赖自定义 HTML**
- **不要依赖 style / embed / script**

### 2. 不要期待自由 CSS

以下内容不应被当作可用能力：

```html
<style>
  .notice { color: red; }
</style>
```

### 3. 不要期待自定义 HTML 布局

例如这类内容，不建议作为正式方案：

```html
<div class="notice">
  <h1>群公告</h1>
  <p>欢迎加入</p>
</div>
```

### 4. iframe 不应作为常规公告能力依赖

虽然 `Markdown` 组件在某些场景下对 `iframe` 有额外判断，但从当前整体渲染策略看，不应该把它当成稳定可依赖的公告语法。

如果你需要嵌入外部内容，建议：

- 优先放普通链接
- 或改成插件式能力

## 六、推荐写法

如果你现在只是想写一份稳定、好维护的群公告，建议按这个模板来：

```md
# 群公告

欢迎加入本群，请先阅读以下内容。

## 1. 群规

- 禁止广告
- 禁止人身攻击
- 禁止重复刷屏

## 2. 新人须知

1. 先修改昵称
2. 阅读历史公告
3. 有问题联系管理员

## 3. 常用链接

- [官网](https://example.com)
- [文档](https://example.com/docs)
```

## 七、什么时候该用哪一种

### 只写一句简介

用：

- 群组基础说明 `description`

### 想让新成员进群自动看到一句欢迎话

用：

- `com.msgbyte.welcome`

### 想写一整页公告、规则、说明文档

用：

- `Markdown Panel`

## 八、建议

如果你后续要让运营或管理员频繁编辑“群公告”，建议在产品和文档层面统一约定：

- 以后“群公告”统一使用 `Markdown Panel`
- 不再让大家尝试 HTML
- 给运营一份 Markdown 模板

这样会比现在不断试错稳定很多。
